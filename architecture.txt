Yes. For your **enterprise email service**, let's build the first API properly rather than putting SMTP logic directly inside the FastAPI endpoint.

We'll start with:

```text
POST /api/v1/emails
```

The architecture should be:

```text
Client
  │
  │ POST /api/v1/emails
  ▼
FastAPI Router
  │
  ▼
Email Application Service
  │
  ▼
Email Provider Interface
  │
  ├── SMTP Provider
  ├── AWS SES Provider
  ├── SendGrid Provider
  └── Other Provider
```

This means your API doesn't care whether the actual email is sent through SMTP, SES, etc.

from pydantic import BaseModel, EmailStr, Field


class SendEmailRequest(BaseModel):
    to: list[EmailStr] = Field(min_length=1)
    subject: str = Field(min_length=1, max_length=200)
    body: str = Field(min_length=1)

# 4. Create the email provider interface

This is an important enterprise pattern.

Create:

```text
src/email_service/application/email_service.py
```

```python
from abc import ABC, abstractmethod

from email_service.domain.email import SendEmailRequest


class EmailProvider(ABC):

    @abstractmethod
    async def send(self, request: SendEmailRequest) -> None:
        pass
```

We're saying:

> Any email provider must implement `send()`.

Later:

```text
EmailProvider
     │
     ├── SMTPProvider
     ├── SESProvider
     ├── SendGridProvider
     └── MockEmailProvider
```

This is much better than putting SMTP code directly in your API.

from email_service.application.email_service import EmailProvider
from email_service.domain.email import SendEmailRequest


class SMTPProvider(EmailProvider):

    async def send(self, request: SendEmailRequest) -> None:

        print("Sending email")

        print(f"To: {request.to}")
        print(f"Subject: {request.subject}")
        print(f"Body: {request.body}")

We're intentionally **not connecting to a real SMTP server yet**.

# 6. Create application service

Update:

```text
src/email_service/application/email_service.py
```

to:

```python
from abc import ABC, abstractmethod

from email_service.domain.email import SendEmailRequest


class EmailProvider(ABC):

    @abstractmethod
    async def send(self, request: SendEmailRequest) -> None:
        pass


class EmailApplicationService:

    def __init__(self, provider: EmailProvider):
        self.provider = provider

    async def send_email(self, request: SendEmailRequest) -> None:
        await self.provider.send(request)
```

Now:

```text
API
 │
 ▼
EmailApplicationService
 │
 ▼
EmailProvider
 │
 ▼
SMTPProvider
```

# 7. Create the API router

Create:

```text
src/email_service/api/email_routes.py
```

```python
from fastapi import APIRouter, status

from email_service.application.email_service import EmailApplicationService
from email_service.domain.email import SendEmailRequest
from email_service.infrastructure.email.smtp_provider import SMTPProvider


router = APIRouter(
    prefix="/api/v1/emails",
    tags=["Emails"],
)


provider = SMTPProvider()
email_service = EmailApplicationService(provider)


@router.post(
    "",
    status_code=status.HTTP_202_ACCEPTED,
)
async def send_email(request: SendEmailRequest):

    await email_service.send_email(request)

    return {
        "message": "Email accepted for processing"
    }
```

# 8. Connect the router to FastAPI

# Why we're doing it this way

Don't start with:

```python
@app.post("/send-email")
async def send_email():
    smtp.connect()
    smtp.login()
    smtp.send()
```

That becomes difficult to maintain.

Instead:

```text
┌─────────────────────────────────────────┐
│ API Layer                               │
│                                         │
│ POST /api/v1/emails                     │
└────────────────────┬────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│ Application Layer                       │
│                                         │
│ EmailApplicationService                 │
└────────────────────┬────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│ Domain                                  │
│                                         │
│ SendEmailRequest                        │
└────────────────────┬────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│ Infrastructure                          │
│                                         │
│ SMTP / SES / SendGrid / etc.             │
└─────────────────────────────────────────┘
```

Then later we can add the enterprise capabilities:

```text
POST /api/v1/emails
        │
        ▼
Validation
        │
        ▼
Idempotency
        │
        ▼
Email Service
        │
        ▼
Message Queue
        │
        ▼
Email Worker
        │
        ▼
Provider Adapter
        │
   ┌────┼─────────┐
   ▼    ▼         ▼
 SMTP  SES    SendGrid
```

**That queue/worker architecture is what I'd recommend before sending real production email.** Your API shouldn't sit there waiting for an SMTP provider to respond; it should generally accept the request, enqueue the email, and let a worker handle delivery, retries, failures, and provider failover.
